# Неделя 3 — Solana Account CLI

Консольная программа на Rust моделирует перевод между двумя учебными аккаунтами.
При каждом запуске Alice имеет 1 SOL, Bob — 0 SOL. Данные живут в памяти.
В сеть программа не обращается. Реальные Devnet-транзакции недель 1–2 находятся в папке evidence.

## Запуск

В Windows можно запустить `demo.cmd` в этой папке без установки Rust: он использует приложенный `bin/solana-account-cli.exe`.

Из исходников (Rust и Cargo):

```powershell
cargo run -- demo
cargo run -- balance alice
cargo run -- convert 0.000000001
cargo run -- transfer alice bob 0.001
cargo run -- transfer alice bob 2
cargo test
```

Для запуска из исходников установи Rust и Cargo. Если команда `cargo` не найдена, проверь установку и переменную PATH.

## Реализованные конструкции

| Конструкция | Применение |
|---|---|
| struct | Account хранит имя и баланс; Receipt описывает перевод |
| enum и match | Command и выбор команды |
| u64 и checked_add/checked_sub | Целые lamports и контроль переполнения |
| Result, Option и ? | Ошибки ввода, поиска аккаунта, недостаточного баланса |
| Vec и HashMap | Аргументы командной строки и коллекция аккаунтов |
| &str, &HashMap, &mut HashMap | Заимствование строк и данных без лишнего копирования |
| ownership | Строки принадлежат структурам и коллекциям |

Сумма преобразуется из десятичного текста без f64: 0.000000001 SOL точно равен одному lamport.
Модель использует фиксированную комиссию 5000 lamports, равную комиссии двух выполненных переводов.
В общем случае комиссию сети надо получать из RPC; это не универсальная константа для любых транзакций.
Перед изменением балансов проверяются оба аккаунта, сумма, комиссия и переполнение.
При ошибке модель оставляет оба баланса неизменными. Это учебное упрощение: неуспешная реальная транзакция может всё равно оплатить сетевую комиссию.

## Проверка

Три unit-теста прошли: точность и границы u64; успешный перевод с учётом комиссии;
сохранение балансов при недостатке средств и переполнении получателя.
